# Progressive result, spoken walkthrough, and lawyer review

## One result that becomes deeper

Create `004_给你的结果/001_咨询结果.md` from `assets/咨询结果模板.md`. Do not create separate competing “basic” and “full” reports.

### Basic judgment version

The baseline result may contain:

- the user’s problem, desired decision, and constraints;
- neutral timeline and fact-claim status;
- material inventory and missing context;
- contradictions, adverse possibilities, and opponent’s strongest factual version;
- concrete urgent/preservation signals already triggered;
- issue and verification map;
- next materials, questions, and reversible practical steps.
- traceable public court cases, official publications, or reliable reporting actually used during the interview;
- a provisional, non-numeric direction tied to the stated facts, evidence status, public sources, and unresolved variables.

For every public source, record source type, publisher, title/case, URL, publication/decision date when available, retrieval time, proposition supported, and limitations. It must visibly say that public search may be incomplete, stale, abridged, or missing contrary cases and is not legal-database verification. Leave the current-law and database-case sections marked “尚未核查”; never complete them from model memory.

### Law-and-case verified version

After the user opts in and verification succeeds, upgrade the same file to include:

- service scope, source/tool coverage, query/finalization time, and lawyer-review status;
- current rules with authority, version, effective date, scope, and traceable citations;
- full-text-verified supporting, contrary, and distinguishing cases with comparability and links to the local Markdown judgment archive;
- two-sided analysis and sensitivity variables;
- supported new findings or hidden risks;
- symmetric options and consequences;
- urgent/save/do/do-not steps with owner, time, and channel;
- what may change the conclusion and the correction path.

The first screen in either version should answer: what matters most, what remains uncertain, and what the user can do next.

## Value claim gate

Call something a new or important finding only if it points to a current rule, located material/contradiction, full-text comparable case, decision-changing unknown, or verifiable low-cost action. Do not manufacture novelty or confidence.

## Spoken walkthrough

Walk through only the most important findings, risks/unknowns, and next steps. Ask what the user wants expanded, use plain-language principles and bounded examples, then use teach-back and invite correction. A material correction updates the workpaper and reruns affected analysis.

At the basic completion point, first state the provisional direction, then ask in one short sentence whether it is enough or the user wants current-law, full-text, and contrary-case database verification. If the user accepts and no Key is configured, say only that a free YuanDian Key is needed and offer to open the registration page. Do not repeat the facts or internal search plan. At verified completion, ask whether the result is enough or the user still needs human confirmation. A decline ends the offer; do not keep upselling.

## Lawyer review

Offer lawyer review when the user asks, remains materially confused, faces high stakes or an important deadline, has unresolved evidence conflict, or is considering an irreversible external action. With agreement, create `004_给你的结果/003_律师复核委托说明.md` and identify the suggested package:

- current consultation result;
- matter workpaper;
- review-request note;
- material inventory;
- user-selected key originals;
- all local judgment files cited by the result, other closely read judgment originals, and a separate full-text index if useful; keep relative links valid when packaging.

Do not send anything. Tell the user to verify recipient details and redact irrelevant personal data without removing legally material context.

The truthful sequence is:

1. package prepared;
2. user voluntarily sends;
3. lawyer confirms receipt;
4. scope and quote are clear;
5. user expressly accepts;
6. lawyer confirms the agreed review has started.

Use `LAWYER_PENDING` through step 5. Only step 6, together with clear scope/quote and user acceptance, permits `LAWYER_ACTIVE`. Before then, do not state that representation, deadline management, filing, or review has begun.

If `001_使用说明与配置/003_服务提供方信息.md` contains a usable contact method, link it after the user chooses human review and describe it only as a way to contact 若凡律师 to ask about review arrangements. Do not infer unpublished professional, location, scope, price, or availability details. If real contact details are not configured, the package can only prepare materials for a lawyer selected by the user. State that limitation before offering the file. In either case, “package prepared” must be spoken as “复核材料已准备，尚未联系律师”; use “律师衔接中” only after the user has actually initiated contact, and never treat a displayed link or QR code as proof of sending or receipt.

## Risk language

Do not rely on blanket statements such as “the user bears all consequences” or “provider has no liability.” Explain the result’s factual, evidentiary, legal-version, tool, case-sample, result-level, and lawyer-status conditions. Preserve non-waivable obligations and request specialist legal review of final production terms.
