# 需要时开启法规与案例核查

这不是第一次咨询的必做步骤。你可以先让系统整理问题、事实、材料、矛盾和风险；只有想核对现行法规、真实案例或形成更完整的条件性分析时，才需要开启。

系统应一次只带你完成当前一步，不要把下面整条技术流程在开场一次讲完。在取得 Key 之前，系统应先用一小段话把叙述中已经出现的整案问题、最少数据和授权边界合并确认；普通用户不必自己规划积分，用户没有另定更低数值时，本次咨询默认最多 `3500 POINT`。这只是安全边界，不是检索档位或需要用完的额度；检索范围由案件实际问题决定。首次收费调用前还要读取实时单次价格；不能先配置、重启，再让你看检索范围，也不能因为账户余额充足就超过授权边界。

## 开启前会先说明什么

法规与案例核查可以：

- 核对当前有效规则、版本、生效时间和适用范围；
- 查找支持、相反和可区分的案例并核验全文；
- 把同一叙述里的多个法律问题放在一张整案问题图中规划，并将取得的裁判全文保存为本地 Markdown 供你回查；
- 把法律规则、案例观察、实践推论和仍需核验的问题分开。

它可能消耗元典账户积分，并会向检索服务发送完成查询所需的最少事实。姓名、证件号、账号、精确地址等与检索无关的信息不应发送。你可以选择现在开启，也可以停在已有的基础梳理。

## 当系统问到时，按三步完成

### 第一步：你亲自取得 Key

打开元典开放平台：<https://open.chineselaw.com/>，注册或登录，在账户控制台创建/复制 API Key。可用积分、价格和活动以平台当时页面为准。

Key 相当于账户凭据。不要把它提交到公开 GitHub、公开群聊、公开文档或截图中。默认使用下面的不回显输入；如果该方式失败或你明确希望少一步，系统可以在说明留存风险后，让你选择直接把 Key 发在当前一对一咨询对话里。

### 第二步：选择一种输入方式

回到本项目对 Agent 说：

> 请帮我开启法规与案例核查。

Agent 会检测已有运行环境：电脑已有 Python 时，优先直接运行跨平台配置工具；Python 不可用时，再选择 Windows PowerShell 或 macOS shell。你不需要自己判断操作系统脚本，也不需要在项目根目录寻找启动器。

默认方式是不回显的隐藏输入。如果窗口没有出现、无法操作，或者你明确选择更省步骤的方式，Agent 应先提示：

> 你也可以直接把 Key 发在这里，我只会用它完成当前配置，不会在回复、报告或状态文件中复述；但它会留在当前对话记录和模型上下文。免费额度及按月重置通常会降低直接经济风险，但仍可能出现额度被他人占用或暂时无法正常使用。你希望继续用安全输入，还是直接发给我？

你选择对话输入后，Agent 可以接收 Key，并把它送入配置程序的交互式输入；不得把 Key 拼进命令行参数。无论采用哪种方式，工具都会：

- 只修改本项目的 `.codex/config.toml`；
- 同时配置 `yuandian-law` 与 `yuandian-case`；
- 测试认证、MCP 初始化和工具列表；
- 把不含 Key 的结果写入 `001_使用说明与配置/006_元典MCP配置状态.md`。

Agent 会优先复用已有 Python；Python 缺失或受策略限制时自动使用 Windows PowerShell 或 macOS shell。只有确实缺少所有可用路线时，Agent 才说明缺少什么、为什么需要、安装来源和影响范围，并在你明确同意后安装最小组件。任何路线都不得通过命令行参数传 Key，也不得在回复、日志、状态文件、底稿或结果中复述 Key。

手工兜底入口位于 `001_使用说明与配置/005_系统工具/`：Windows 使用 `开启法规与案例核查.cmd`，macOS 使用 `开启法规与案例核查.command`。通常无需自行运行。

### 第三步：重启后继续，不重新讲

配置变更后完全退出并重启 Codex，重新打开同一项目，直接说：

> 继续核查。

系统会读取已有工作底稿，从中断处继续。它必须在第一次实体核查前：

1. 调用法规 Server 检索《民法典》第一千零四十三条，核对原文、规范名称和来源；
2. 确认案例 Server 能列出案例检索与详情工具；
3. 把时间、Server、工具、结果和失败原因写入 `003_内部工作区/002_能力检查.md`。

脚本测试只证明 Key、网络和 MCP 协议连通；Codex 内真实工具调用也通过，才算完整链路通过。通过记录晚于最新配置状态时可复用，避免每个案件重复消耗积分。Key 或配置变化后需要重测。

如果脚本链路测试失败，先按状态文件处理并重跑，不要把“已写配置”误认为配置成功；此时无须为了失败结果重启。如果 Codex 端能力失败，已有的基础梳理同样不会丢失，也不需要重来。系统应准确说明当前缺哪一步；在完成核查前，不得把模型记忆或搜索摘要写成已核验的现行法、案例观察或最终实体结论。

## Key 存储与安全

为了降低门槛，脚本把 Key 以明文 Header 写入项目自己的 `.codex/config.toml`。任何能读取该文件夹的人都可能看到 Key，因此：

- 不要公开上传 `.codex/config.toml`；
- 不要把整个已配置目录发给他人；
- 对话输入虽然允许，但只适合你理解并接受当前对话/模型可能保留 Key 的情形；需要更高安全性时使用隐藏输入；
- 如果项目位于 OneDrive、iCloud、Dropbox 或其他同步目录，`.gitignore` 不能阻止云同步；请检查同步和共享权限，或把项目移到合适的本地目录；
- 怀疑泄露时到元典控制台撤销并重新生成；
- 需要更高安全级别时，可改用 Codex 的环境变量 Header 方案。

## 核查质量

- 主要法律结论记录 MCP 名称、查询时间、规范版本和可回查来源。
- 法规 MCP 负责现行规范；`$prc-case-research` 默认按整案争点、依赖关系和不确定性执行正反向、区分、证据、程序、权威与语义检索，不按积分档位决定强度。
- 案例全文通常从整案 `20–50` 份开始审阅并逐份保存到 `004_给你的结果/004_案例全文/`；如果仍有重要争点或分歧，可继续扩展，没有机械上限。咨询结果直接链接本地文件。
- 官方网页用于补充当前程序、交叉核验和发现遗漏，不替代规范效力核验或案例全文。
- 工具失败、法律状态不明、样本不足、来源冲突或积分不足都写成“需核验”，必要时转真人律师。

元典 MCP 的官方接入说明：<https://open.chineselaw.com/mcp-config/>。
